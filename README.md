# KTH Activities Helper

Discord-бот на discord.py, FastAPI backend и MySQL. Бот обращается к backend по HTTP;
модуль командных каналов работает напрямую с Discord и от БД не зависит.

## Что изменено

- Backend проверяет соединение с БД перед выдачей из пула (`pool_pre_ping`) и
  заменяет старые соединения при следующем использовании (`pool_recycle`).
  `DB_POOL_RECYCLE_SECONDS` по умолчанию 3600; при необходимости установите
  значение меньше серверного `wait_timeout`. Это исправляет использование
  соединений, закрытых после простоя, но не скрывает недоступность самой БД.
- При сбое API рулетка отвечает пользователю и освобождает блокировку.
  Одновременные упоминания одного пользователя не запускают два броска.
  Запись результата автоматически не повторяется: потеря ответа могла произойти
  после сохранения броска.
- У команд userinfo/register один `defer()`; расширения загружаются в
  `setup_hook()`, а повторный `on_ready()` только пишет в журнал.
- Вызовы API ограничены `API_TIMEOUT_SECONDS` (по умолчанию 15 секунд).
- Исправлена команда запуска в Dockerfile бота.

## Модуль команд

Файл: `discord_bot/commands/teams.py`. Загружается вместе с рулеткой и userinfo.
Перенесены только `/create-team` и `/archive`. Команда `/rating` не добавляется.

Настройки в окружении бота:

| Переменная | По умолчанию / назначение |
| --- | --- |
| `TEAM_GUILD_ID` | Не задана; можно ограничить команды конкретным сервером |
| `TEAM_ADMIN_ROLE_ID` | Не задана; рекомендуется задать ID роли организатора |
| `TEAM_ADMIN_ROLE_NAME` | Секретарь ЦК импрува; используется, если ID роли не задан |
| `TEAM_TEXT_CATEGORY_ID` | 563361695699959811 - текстовая категория из Go-бота |
| `TEAM_VOICE_CATEGORY_ID` | 571337094165954610 - голосовая категория из Go-бота |

Даже без `TEAM_GUILD_ID` команды работают только на сервере, где есть обе
настроенные категории. При заданном ID организатора совпадение названия другой
роли не даёт доступ. Команды доступны только в сервере, не в личных сообщениях.

Боту нужны **Manage Roles**, **Manage Channels**, **View Channel**, **Send Messages**.
Его роль должна находиться выше создаваемых командных ролей. В Developer Portal
должны быть включены **Server Members Intent** и **Message Content Intent**
(последний нужен рулетке). Бот использует scopes `bot` и `applications.commands`.

### /create-team

Название и 2–8 разных участников. Создаёт роль, выдаёт её участникам и создаёт
закрытые текстовый и голосовой каналы. Организаторская роль и бот получают доступ.
Дублирующее название роли отклоняется. При частичной ошибке бот пытается удалить
созданные ресурсы; если откат не удался, показывает оставшиеся ID.

### /archive

Вызывать в текстовом канале команды внутри настроенной категории.

- Без аргумента показывает роли с явным доступом к каналу.
- С аргументом `role` (выбор Discord-роли) запрещает командной роли отправку
  сообщений и создание веток. Текущим участникам роли сохраняет персональный
  доступ к чтению и также запрещает запись, включая сообщения в ветках.
- Список участников получает полностью, с пагинацией, а не только первые 1000.
  Список сохраняется в ответе как `participants.txt`. Посторонние настройки
  доступа сохраняются. Права администраторов Discord по-прежнему имеют приоритет.
- При частичной ошибке изменения прав выполняется попытка отката с отчётом.
  Для очень больших команд действуют ограничения Discord на число перезаписей прав.
- После изменения прав предлагает отдельно удалить голосовые каналы с явным
  доступом этой роли **только в настроенной голосовой категории**.
  Удаление привязано к ID; совпадение названий не используется.
- Подтверждение доступно автору команды, пока у него есть роль организатора,
  в течение пяти минут. Перед удалением категория и доступ роли проверяются снова.
- «Оставить голосовые каналы» и истечение времени сохраняют голосовые каналы;
  текстовый канал остаётся архивом. После перезапуска бота для нового подтверждения
  нужно снова вызвать `/archive`.

Существующие каналы Go-бота поддерживаются по явному разрешению командной роли
и категории. База для привязки команд не требуется. Ограничение имени роли
квадратными скобками заменено проверками категории и доступа.

## Обновление VDS

Изменения нужны **и backend, и Discord-боту**. Одного перезапуска бота недостаточно
для исправления пула MySQL.

1. Обновить исходники и зависимости обоих сервисов.
2. Проверить настройки категорий и роли организатора. Значения категорий по
   умолчанию взяты из исходного Go-бота.
3. При использовании текущего Docker Compose:
   `docker compose up -d --build fastapi discord-bot`.
   Не удалять том MySQL. Dockerfile обоих сервисов использует
   `ENV_FILE_NAME=.env.docker.dev`; сохраните рабочие файлы окружения на сервере
   или передайте те же переменные контейнерам.
4. Проверить журналы и регистрацию восьми slash-команд, затем создание/архив
   на тестовой команде. Остановить старый Go-бот после проверки переноса.

Без Docker запускать из корня проекта: `python -m discord_bot.demo_kth`.
По умолчанию настройки читаются из `discord_bot/.env`, затем корневого `.env`.
Пример - `discord_bot/.env.example`; секреты на VDS менять не нужно.
GIF по умолчанию берутся из `discord_bot/resources`.

## Проверки

Изолированные регрессионные тесты не подключаются к Discord, osu! или рабочей БД:

```text
python -m pip install -r tests/requirements.txt
python -m pytest tests -q -o asyncio_mode=auto -o asyncio_default_fixture_loop_scope=function
```

Проверяются восстановление закрытого соединения (SQLite), обработка ошибок API,
повторные/одновременные упоминания, загрузка команд, права, откат и кнопки архива.
Отдельный тест MySQL пропускается без `TEST_MYSQL_URL`.
Для него используйте изолированную тестовую БД с URL вида
`mysql+asyncmy://user:password@host:3306/test_db`: он устанавливает
`SESSION wait_timeout=1` на своём соединении и проверяет первый запрос после простоя.
Старые тесты `backend/tests` имеют отдельные зависимости; часть обращается к osu!.
